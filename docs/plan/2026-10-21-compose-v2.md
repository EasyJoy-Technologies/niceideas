# Compose v2: implementation plan (draft for confirmation)

Design: `docs/design/mockups/v4/compose-v2.html` (review/v4/compose-v2.png). Status: brand (v1.0.52) and info pages v4.1 (v1.0.53) are on staging; compose is the only v4 item not yet built.

## Target behaviour (from the draft)
- One toolbar row from the card's left edge: image, audio | format buttons | "…" overflow | short/long toggle | Post.
- Short: editor at least 5 lines and grows with content; images appear as thumbnails under the text (each with ✕); audio appears as a small player bar.
- Long: title row, editor at least about 420px and grows with content; images and audio go in at the cursor (WYSIWYG); H / B / I / link / lists / checklist shown; H3, numbered list, quote, strikethrough, inline code, code block and divider sit under "…".
- Phone: same single row with fewer buttons; the rest go under "…".
- Without JS: plain textarea + image/audio file inputs + short/long radio (still posts).

## Placement and boundaries
| Layer | Change |
|---|---|
| Client editor (new `src/client/compose/`) | Tiptap (ProseMirror, MIT) editor, toolbar, media nodes, serializer → normalized document JSON. Bundled by esbuild into `public/scripts/compose.js` at build time, loaded only when the compose box is on the page. |
| HTML (`src/server/share/compose-box.ts`) | New markup: toolbar row, toggle, no-JS fallback fields. |
| Styles (`public/styles/compose.css`) | Rewritten per draft, including the phone layout. |
| Route (`compose-route.ts`) | Same endpoint; adds error codes for audio. |
| Posts (`src/server/posts/web-compose.ts` + new `web-compose-doc.ts`) | Accepts `mode` and either `doc` (JSON blocks: markdown text / todo / image#i / audio#i referencing uploaded files by index) or the plain fallback. Validates with zod, ingests the files in order (image and audio), builds the document, and passes the chosen kind (short → `short`, long → `article`, kind locked). |
| Feed (`feed-card.ts`) | Short posts with media show the text and then the images as thumbnails plus audio. Today these become article cards. |
| i18n | About 20 new keys (toolbar labels, overflow items, toggle, audio errors) in all 40 locales. |

No DB migration: documents already support markdown text, todo, image and audio blocks.

## Decisions to confirm
1. **Editor library: Tiptap.** About 90 KB gzipped, loaded only with the compose box. The alternative is a self-built contenteditable editor: smaller, but paste, undo and IME are much less reliable.
2. **Short posts with images stay "short".** The feed shows the text and then thumbnails, matching the draft. Today any image turns a post into an article card.
3. **Short-mode limit: 500 characters**, which is the existing short threshold. A counter appears near the limit; over the limit the editor suggests switching to long. Long allows 20,000 characters. Audio: up to 10 per post, using the existing 150 MB per-file limit.

## Verification
- Unit tests: doc JSON → document (ordering, file-index mapping, limits, rejecting unknown blocks).
- Integration tests: long post with inline image and audio in order; short post with images stays short and shows in the feed; no-JS fallback; audio errors.
- Headless screenshots: desktop and phone, both modes, empty and filled. A real click-through on staging.
- `pnpm check` and build pass; deploy to staging only.
