# S2（v1.0.64）后台任务进程 — 实现计划（2026-10-24）

依据：`2026-10-23-nicenote-source-api.md` §1、§5–§7、§11（已确认）；契约 nicematrix-backend `docs/integration/niceideas-share.md` v1（API 1.2.743）§4、§5、§7。

## 1. 进程
- `scripts/worker.ts` → `dist/worker.mjs`，常驻进程，systemd `niceideas-staging-worker`（生产 `niceideas-worker`，上线生产时另行确认）。
- 三条并行的循环：出站通知、媒体（一次一个）、头像。没活时每 2 秒查一次数据库。
- 抢任务用 `FOR UPDATE SKIP LOCKED` + 租约（处理中定期续租）。进程崩溃后租约到期由别的循环重新领取，多进程也不会重复处理。
- 收到 SIGTERM：不再领新任务，杀掉正在跑的 ffmpeg / magick，未完成的任务等租约到期后重做。
- staging 资源：Nice=10、空闲 IO、CPUQuota=80%、MemoryMax=1G，`PrivateTmp`。
- 部署脚本：迁移后如果 worker 服务已安装就一起重启，并检查是否在运行。

## 2. 出站通知（契约 §4.1、§4.2）
- 签名同来源接口，`X-NM-Service: niceideas`，发到 `NICEMATRIX_API_URL`。
- 2xx = 完成。400 / 404 / 409 / 410 / 413 / 422 = 永久失败（记录，不再重试）。其他（网络、5xx、429、401/403）按 1 分钟、5 分钟、30 分钟、之后每小时重试，满 24 小时记为最终失败。
- 没配密钥时不发，队列保留。
- 已有用户补登记：迁移 0014 给现有资料各排一条“登记用户”（按 userId 去重）。

## 3. 媒体（契约 §4.2、§4.3、§7）
- ref → 媒体的对应关系记在 `media_job.media_id`（同一内容两个 ref、或网页上传过同一文件，都能复用一份媒体）。S1 加的 `media.source_ref` 没有数据，迁移 0014 删除。
- 拉取：只允许取件路径；签名 GET，流式写临时文件，≤ 2 GiB，边下边算 sha256。本地重试 3 次（1 分钟、5 分钟），仍失败报 `fetch_failed`；410 或地址已过期报 `fetch_expired`；进程反复中断（3 次）报 `temporarily_unavailable`。
- 同一用户已有相同内容（sha256）的媒体就直接复用，不再处理。
- 图片：
  - JPEG / PNG / WebP / GIF / AVIF 用 sharp；HEIC / HEIF / BMP 先用 ImageMagick（libheif）转成 PNG 再进同一流程；先读尺寸，超过 1 亿像素报 `too_large`。
  - 动图（GIF、WebP）：网页版本保留动画，兜底图用第一帧。帧数×尺寸超过上限时只保留第一帧（不报错）。
  - 超长图：缩放后高度 ≤ 16383 用 WebP，更高的用 JPEG（有透明用 PNG）；高度再封顶 65500（按比例缩窄）。**不切片**。页面对这类图片直接用 `<img srcset>`。
  - 仍然去掉全部元数据，不保留原图。
- 音频（ffprobe 判断真实格式）：
  - AAC（M4A / MP4 / ADTS）：只重新封装为索引前置的 M4A，不重编码。
  - MP3：只复制音频流，去掉标签，不重编码。
  - 其他（WAV、FLAC、ALAC、APE、WMA、AMR、OGG、Opus、AIFF、CAF 等）：转码为 128 kbps AAC / M4A。
  - 一律去掉元数据（含录音的位置信息）。不限时长。
  - 有真视频轨或没有音轨：`unsupported_format`；读不了：`decode_failed`；转码失败：`transcode_failed`。
- 失败分两种：暂时性（`failed`，后台推送新地址时重新排队）；永久性（`rejected`，同一用户同一 ref 不再拉取，页面显示“暂不可用”）。
- 完成或失败后，更新这个用户所有引用这个 ref 的帖子：
  - 在线的帖子：媒体复制到公开存储、关联到当前版本、重算封面和 media_state、刷新页面缓存。
  - 下架的帖子只关联，不公开。
- 事件：
  - 媒体失败：按帖子发 `media_failed`（refs + reason）。推送时文档里有已永久失败的 ref，也补发一次。
  - 帖子媒体全部就绪：发 `media_ready`。从“处理中”或“部分失败”变成完成时发，不管是任务完成还是新推送导致的。

## 4. 头像（方案 §6）
- 资料新增 `avatar_source`（跟随的 NiceMatrix 头像地址）；新表 `avatar_job`。
- 跟随规则不变：地址变了就排一个下载任务，下载完成前继续显示旧头像。
- 下载：只允许 https 和公网 IP（每次连接都检查，防内网访问），不跟随跳转，≤ 10 MB，15 秒超时，必须能解码成图片（≤ 2500 万像素）。
- 生成一份 256×256 WebP 存到公开存储，资料改用自己的地址，再删掉旧的自有头像。
- 失败：暂时性按通知的节奏重试 24 小时；永久性放弃，保留旧头像。
- 迁移 0014 给现有的外部头像都排一次下载；注销完成时删除自有头像。

## 5. 迁移 0014
`media_job`：加 `media_id`，状态加 `rejected`，加索引；`media` 删 `source_ref`；`profile` 加 `avatar_source`；新表 `avatar_job`；补登记用户和头像任务。

- 媒体：用本地模拟取件服务覆盖以下情况：
  - 图片：JPEG、PNG（透明）、动图 GIF、BMP、HEIC、超长图。
  - 音频：AAC/M4A、MP3、WAV、FLAC、Opus。
