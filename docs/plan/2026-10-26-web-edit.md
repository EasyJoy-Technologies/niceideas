# 网页编辑帖子（W7，分期 E）— 方案与设计稿（2026-10-26，Xianglin 已确认）

依据：Xianglin 2026-10-23 的决定（`docs/plan/2026-10-23-nicenote-source-api.md` §12）：所有来源的帖子都能在网页编辑；保存后生成新版本，链接不变；应用之后再推送就覆盖网页修改（谁后改谁生效），不新增事件。

设计稿：`docs/design/mockups/edit/`。截图都是用现有代码渲染的真实页面，编辑页直接复用现有发布框。
1. `1-post-menu-desktop.png` / `1-post-menu-phone.png` / `1-app-post-menu-desktop.png`：帖子的“⋯”菜单里，“删除”上面加一项“编辑”。只有作者能看到，帖子页和自己主页上的卡片都有。
2. `2-edit-article-desktop.png` / `-phone.png` / `-dark.png`：编辑页 `/p/{slug}/edit`。页头是“编辑帖子”和“取消”，下面是和发布框一样的编辑器，已经填好当前内容；按钮从“发布”改为“保存”。**不显示短内容 / 长文章切换**：帖子类型保持不变（Xianglin 2026-10-26），短内容按短内容的限制编辑。
3. `3-edit-app-post-desktop.png`：从应用分享来的帖子，编辑页和网页帖子完全一样，不加任何说明（Xianglin 2026-10-26：页头“编辑帖子”和编辑框之间不加提示文字）。
4. `4-after-save-desktop.png`：保存后回到帖子页，作者行的时间后面显示“已编辑”，鼠标悬停时显示最后编辑时间。

## 行为
- 保存：生成新版本，链接、点赞和评论都不变。去掉的图片和音频会移回私有桶，加进来的图片和音频和发帖时一样上传。
- 限制：长度、图片和音频数量、频率都和发帖一样（修订有频率上限）。
- 不能编辑的情况：帖子已删除、被下架、账号正在注销，或者应用分享来的媒体还在处理中。这时“编辑”不显示；直接打开编辑页会显示原因。
- 不开 JS 时：编辑页退回普通文本框，可以改标题和文字。图片保持原样，也能添加新的。
- “已编辑”：只要帖子发布后内容改过就显示，不管是在网页上改的还是应用重新分享的。

## 实现位置
| 层 | 改动 |
|---|---|
| 服务 `src/server/posts/edit-post.ts`（新） | 加载自己的帖子 → 检查能否编辑 → 用 `web-compose-doc` 生成文档 → 复用 `syncPost` 的新版本流程（加锁、换版本、移媒体）。 |
| 文档转换 `src/server/posts/edit-source.ts`（新） | 把当前文档转成编辑器内容：API 格式（markdown、待办、图片、音频）直接转；应用分享来的文档（rich 行和 runs）转成同样的编辑器节点，已有媒体按 media id 引用，不重新上传。 |
| 页面 `src/app/p/[slug]/edit/route.ts` + `src/server/share/edit-page.ts`（新） | 复用 `composeBox`，加上预填内容、目标地址和“保存”。 |
| 编辑器 `src/client/compose/` | 读取页面里的初始内容（`<script type="application/json">`，符合 CSP），兼容已有媒体（按 id 引用的缩略图和音频条）。 |
| 菜单 `src/server/share/post-menu.ts` | 加“编辑”。 |
| 应用覆盖规则 `src/server/nicenote/push-content.ts` | 新列 `post.web_edited_revision`（迁移 0016）：网页保存时记下当时的应用版本号。之后应用推送时，版本号**更大**才覆盖网页修改；版本号相同的重发（后台重试）不覆盖，返回 `changed: false`。 |
| 文案 | 约 6 个新键（编辑、编辑帖子、保存、已编辑、最后编辑时间、不能编辑的原因），40 种语言全部翻译。 |

## 已确认（2026-10-26）
1. 设计稿：编辑页不加说明文字，不显示类型切换。
2. “已编辑”也包括应用重新分享带来的修改。
3. 应用重发同一个版本不覆盖网页修改，只有版本号更大才覆盖。

## 验证
单元测试：文档转换（两种格式、媒体引用）、覆盖规则。集成测试：网页编辑两种来源的帖子、应用重发和新版本推送、媒体在两个桶之间移动、限流。浏览器检查：桌面和手机、深色、不开 JS。先上 staging。
