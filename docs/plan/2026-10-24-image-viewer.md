# 图片查看器 + 大图版本（v1.0.65）— 方案

状态：Xianglin 2026-10-24 14:35 确认；v1.0.65 已实现（见 changelog/v1.0.65.md），未部署。设计稿：`docs/design/mockups/viewer/`（截图 + 主题样式和脚本）。

## 1. 要解决的问题
- 现在点图片只是全屏显示：不能放大、缩小、拖动；长截图被压成一条，看不清；一篇帖子多张图不能切换。
- 最大的版本只有 1600 px，就算能放大，大照片的细节也看不清。

## 2. 交互
| | 手机 | 电脑 |
|---|---|---|
| 打开 | 点图片，从原位置放大打开 | 同左 |
| 放大 / 缩小 | 双指缩放；双击放大 / 还原 | 点图片放大 / 还原；滚轮或触控板缩放；右上角放大镜按钮 |
| 拖动 | 放大后拖动 | 放大后拖动 |
| 多张图 | 左右滑动；左上角“2 / 4” | 左右箭头按钮、键盘 ← →；左上角“2 / 4” |
| 长图（高 ≥ 宽 × 3） | 按屏幕宽度显示，从顶部开始，上下拖动看全图 | 按帖子正文宽度（42rem）显示，从顶部开始，滚轮往下看 |
| 关闭 | 右上角 ×；下拉（长图除外，长图上下拖动是翻看）；手机返回键 | ×、Esc、点图片外面 |

- 一组图：帖子页正文里的所有图片按顺序为一组；时间线每张卡片的小图为一组。到第一张 / 最后一张就停，不循环。
- 说明文字：图片说明（没有就用图片描述），在底部显示；放大后或长图往下看时自动隐藏。
- 长图和放大后的大图，右边有一条细的位置条。
- 加载超过 1 秒显示加载圈；加载失败显示“图片加载失败”。
- 系统开了“减少动态效果”时不播放打开 / 关闭动画。
- 没有 JS 时：点图片直接打开图片（以后打开的是大图版本）。
- 无障碍：对话框角色、焦点锁定在查看器内、关闭后焦点回到打开它的那张图片（页面不跳动）；按钮都有朗读文字。
- 从右到左的语言（阿拉伯语、希伯来语、波斯语、乌尔都语）：查看器的按钮和计数按从左到右排列，和滑动方向一致（PhotoSwipe 只支持从左到右滑动；否则顶栏镜像而箭头不镜像，计数会显示成"4 / 1"）；说明文字保持自己的方向。实现时用浏览器检查发现并修正。

## 3. 外观
- 背景深色（#111827），浅色主题和深色主题一样。
- 按钮：44 px 圆形，深色半透明底加细边，图标用网站现有的线条图标；“2 / 4”是同样底色的胶囊。照片再亮、截图再白都看得清。
- 电脑上图片四周留白，按钮、箭头和说明都在图片外面；手机上图片铺满屏幕宽度。
- 字体、圆角、颜色都用现有 tokens.css 的变量。

## 4. 大图版本
规则（新上传的图片，网页上传和乐趣记事本分享都一样）：
- 原图比现有最大版本（1600 px）更宽时，多生成一个大图版本：不超过约 1670 万像素（4096 × 4096 的面积），每边不超过 16383 px（WebP 上限），不放大，WebP 质量 82。
- 例子：1200 万像素手机照片 → 原尺寸保存；4800 万像素 → 缩到约 1670 万像素；全景照片按面积缩，不会被压得很窄；长截图（宽度不到 1600）不需要，现有版本已经是原宽。
- 动图不生成（每一帧都要算，太大），查看器用现有的动图版本。

为什么不用“长边 4096 px”或“原尺寸”：
- 长边 4096：全景图会被压得很矮（例如 12000 × 3000 → 4096 × 1024），比按面积缩差很多。
- 原尺寸：1 亿像素的原图，一张就是几十 MB，手机打开容易卡死或崩溃。约 1670 万像素的大小手机能稳定显示，4800 万像素的照片放大看也足够清楚。

什么时候下载：查看器把所有版本都告诉浏览器，浏览器按屏幕需要选。
- 手机打开时用现有版本（960 或 1600 px），放大才下载大图版本。
- 电脑高清屏（2 倍屏）打开时就会用大图版本，普通屏放大时才下载。

成本：设计稿里那张 5568 × 3712 的照片，现有版本合计约 0.56 MB，大图版本 2.6 MB。一般手机照片估计每张多 1–3 MB 存储（没有用真实手机照片测过）。

已有的图片：原图没有保存，补不了大图版本，查看器用现有的 1600 px 版本，放大、拖动、切换照样能用。

## 5. 实现
- 查看器用 PhotoSwipe 5（MIT 许可，约 21 KB gzip，没有其他依赖）。和 compose.js 一样在构建时打包成我们自己的脚本，同源加载，不违反现有的内容安全策略（设计稿已在生产环境同样的策略下测过，没有报错）。
  - 不自己写的原因：手机上双指缩放、惯性拖动、下拉关闭、各种浏览器的触摸差异都要做对，自己写风险大，测试也只能靠模拟器。
- 前端：`src/client/viewer/`（查看器设置、说明文字、位置条、返回键各一个文件），打包到 `public/scripts/viewer.js`；主题样式 `public/styles/viewer.css`。只在有图片的页面加载（帖子页、时间线、发现、个人主页、搜索）。
- 删掉 share.js 里旧的查看器代码和 share-page.css 里的 `.ni-lb` 样式。
- 服务端：
  - `image.ts` 生成大图版本；图片数据（JSON）加一个可选的 `large` 字段，不需要数据库迁移。
  - 存储、删除、公开 / 私密切换和占用统计都把大图版本算进去。
  - `media-html.ts` 统一输出图片链接（帖子页和时间线共用一个函数）：链接指向最大的版本，并带上尺寸和所有版本的列表。
- 多语言：新增 5 个词条（缩放、上一张、下一张、图片加载失败、图片查看器），40 种语言同一个提交里全部翻译；“关闭”沿用现有词条。
- 测试：
  - 大图规则：1200 万、4800 万像素，全景，长截图，小图，动图，透明图。
  - 页面输出的属性。
  - 部署前用浏览器在 staging 的真实页面上截图检查：手机、电脑，浅色、深色。
