# v1.0.68 — 2026-10-26

Web editing of posts (plan `docs/plan/2026-10-26-web-edit.md`, design `docs/design/mockups/edit/`).

## Added
- "Edit" in the author's "⋯" menu (post page and feed cards), above Delete; shown while the post is live and, for NiceNote shares, its media are processed.
- Edit page `/p/{slug}/edit`: heading and Cancel, then the compose box opened with the post's content (title, text, lists, checklists, quotes, code, links; images and audio in place for articles, under the text for short posts). No explanatory text. The post keeps its type: no short / long switch; short posts keep the short limit. Save → new revision, same link, likes and comments. Works without JS (Markdown text, kept media, new files).
- Any source can be edited: web posts, app posts and NiceNote shares (their rich text opens as editor content; stored media are kept by id with their captions). Media dropped by an edit move back to the private bucket.
- "Edited" after the time in the post header (tooltip: last edit time) whenever content changed after publishing — web edits, app updates and re-shares (not media finishing). Replaces the old "Edited {time}" line in the post footer.
- App updates after a web edit: the same version (a retry) leaves the web edit in place; a newer version replaces it.
- 8 new labels in all 40 languages.

## Changed
- App syncs and web edits share one revision switch (`src/server/posts/switch-revision.ts`).

## Database migrations
- `0016_post_edits`: `post.edited_at`, `post.web_edited` (additive; existing posts with several revisions count as edited)
