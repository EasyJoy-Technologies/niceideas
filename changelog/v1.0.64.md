# v1.0.64 — 2026-10-24

## Added
- Background worker `dist/worker.mjs` (systemd `niceideas-staging-worker` / `niceideas-worker`, low priority, own CPU and memory limits; plan `docs/plan/2026-10-24-s2-worker.md`), phase S2 of NiceNote sharing:
  - NiceNote media: signed fetch of the backend's grants (≤ 2 GiB), web versions stored, every share using the media updated (page, cover, media state). HEIC / HEIF and BMP supported (ImageMagick); animated GIF / WebP stay animated; very tall images get JPEG / PNG renditions (at most 65500 px high, no slicing); audio: MP3 kept exactly as received, AAC re-wrapped without re-encoding, other formats encoded to AAC / M4A; ID tags kept (location tags removed from converted files); no duration limit.
  - Failures reported per reason (`media_failed`); temporary ones come back with the next grant, permanent ones are never fetched again for that owner and ref; `media_ready` when a post's media are complete.
  - Notifications to the backend delivered (user registration, post events), signed, retried for 24 hours.
  - Avatars downloaded from NiceMatrix (public https only, ≤ 10 MB) into the public bucket as 256 px WebP; removed with the account.
- Maintenance drops delivered notifications after 30 days.

## Changed
- Images too tall for WebP (also web uploads) get JPEG / PNG renditions instead of failing.
- Image markup comes from one helper for posts and feed cards.

## Database migrations
- `0014_share_worker`: `media_job.media_id` (ref → media, replaces `media.source_ref`), state `rejected`; `profile.avatar_source`; table `avatar_job`. Data: existing users queued for registration with the backend, existing avatars queued for download.
