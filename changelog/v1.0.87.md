# v1.0.87 — 2026-10-27

Generic cookie banner with categories (Xianglin 2026-10-27 21:22: "不要把确认弹框的确认面搞太窄了", plan approved 21:25).

## Changed
- Cookie banner first layer is generic: "We use cookies", cookies and similar technologies for the site to work and, with permission, optional cookies (example: usage analytics); no vendor or "analytics cookies" wording. Buttons: Reject all / Accept all (equal weight) and Customize.
- Customize panel: Necessary (locked on, "Always on") + one switch per offered category, Save choices. Categories: `analytics` (offered while GA4 or Clarity is configured), `ads` (strings ready, offered only once an ad vendor exists). The privacy page's "Cookie settings" opens the panel with the current choices.
- `ni_consent` now stores `v<version>.<category>-<0|1>…` (e.g. `v1.analytics-1`); old `granted` / `denied` values read as version 1 analytics, so nobody is asked again. The banner asks again when a new category is offered (earlier grants keep working) or `CONSENT_VERSION` is bumped (earlier grants stop counting).
- Vendors are registered per category (src/client/consent/vendors.ts); Google Consent Mode / Clarity consentv2 receive every category (ads stays denied). Withdrawing a category deletes its tools' cookies and reloads.
- consent.js is now bundled from TypeScript (src/client/consent: store / vendors / banner / index; generated, git-ignored like compose.js and viewer.js). The first automatic prompt no longer moves the focus; Cookie settings focuses the first switch.
- Privacy policy (40 locales): `ni_consent` row and §5 text describe accept/reject all or choose by category. Effective date unchanged (2026-10-27; clarification only).
- i18n: consent.title/text changed, consent.accept/reject → acceptAll/rejectAll, new customize, save, alwaysOn, cat.{necessary,analytics,ads}.{title,text}, 40 locales.
