# v1.0.66 — 2026-10-25

Cost and performance release (plan `docs/plan/2026-10-25-remaining-work-and-cost.md`: W1, W2, W3, R1–R4, P2, P3).

## Changed
- Worker wake-up: committing a due outbox / media / avatar item sends `NOTIFY niceideas_work` (database triggers, delivered on commit, never for rolled-back work). The worker listens on one dedicated connection and starts at once (tens of milliseconds instead of up to 2 s). Idle loops sleep until their next scheduled item (retries, lease ends), at most 60 s; while the listening connection is down they poll every 2 s as before and reconnect with backoff (each reconnect wakes every loop).
- One stored copy per media file: publishing moves renditions from the private to the public R2 bucket (server-side copy, then delete) instead of copying them through the server; withdrawals move them back. Moves can be repeated safely. Halves media storage. `dist/media-single-copy.mjs` converts existing media once per environment.
- JPEG / PNG fallback rendition of new images: at most 1200 px wide (was 1600), the size share cards are made from; about 6–8 % less per photo.
- Media cache: `public, max-age=300, s-maxage=3600` (browsers 5 minutes as before, Cloudflare edge 1 hour) → fewer R2 reads. Withdrawn media may stay at the edge for up to 1 hour until deletions also purge the CDN.
- Versioned static files (`/styles/*?v=`, `/scripts/*?v=`) and fonts: cached for a year (immutable); brand images one day. Before: `max-age=0` from the server.
- Image processing in every process: no libvips operation cache, one libvips thread per image (same speed in measurements, less memory); the worker keeps two threads.
- `WEB_CONCURRENCY=1` runs the web server in a single process (no idle cluster primary).
- systemd units: `MALLOC_ARENA_MAX=2` for web and worker (libvips memory is returned to the system).

## Added
- Daily maintenance drops processed account-event ids older than 90 days (they hold only ids and times).
- Off-site database backups: `dist/backup-offsite.mjs` copies the daily dump to the private R2 bucket under `backups/` and keeps 30 days there (`deploy/niceideas-backup.service`).
