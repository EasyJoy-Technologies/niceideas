# v1.0.92 — 2026-11-10

Post-page images that are narrow or tall now sit in a frame tinted with the image's own colour (Xianglin 2026-11-10 16:02: "开始做吧". Choices, 15:55: store the dominant colour at upload rather than read it live, and older images fall back to the existing grey; 14:02: tall or narrow images should not be stretched, and their sides get a backdrop matching the image's tone).

## Changes
- **Image frame on post pages** (the article and short-post body, web posts and NiceNote shares):
  - Images are never shown wider than they really are. They used to be stretched to the column width, so small images were blurry.
  - Images are at most about one screen tall: `min(80vh, 48rem)`. Before, a phone screenshot or a portrait photo could be several screens tall.
  - The frame always spans the column. Space beside a narrower or height-capped image shows the image's dominant colour, softened over the page surface (40 % light theme, 35 % dark theme; token `--ni-image-tone`). The colour also shows while the image loads.
  - Older images have no stored colour and show the existing surface-2 colour, so no back-fill is needed.
  - Long images (height ≥ 3 × width, the image viewer's own rule) show their top part at full frame width, tagged "长图 / Long image" in the bottom inline-end corner (left in RTL). Tapping opens the full image in the viewer, which starts at the top as before.
  - Landscape photos and other images that fit look the same as before.
  - Phones: edge to edge as before, without rounded corners.
- **The dominant colour is read at upload** (web uploads and NiceNote shares). It comes from the smallest rendition already written, using a 64 px thumbnail with transparency counted as white and the first frame of animated images. It is stored as `tone` ("#rrggbb") in the image's `variants` JSON, so no migration is needed. If the colour can't be read, nothing is stored and the upload still succeeds.
  - The page CSP allows no style attributes, so the colour is drawn as an inline SVG `fill`. The renderer only outputs values that are a valid "#rrggbb".
- **Image viewer:** the open and close animation now starts from the visible part of the image: the letterboxed image, or the top of a long image. Before, it started from the whole `<img>` box. This is `src/client/viewer/thumb-bounds.ts`, which follows the computed `object-fit` / `object-position`. Feed thumbnails behave the same as before.
- i18n: 1 new key, `share.media.longImage`, in all 40 locales.
- Test fix: `feed-pages.test.ts` expected "Joined October 2026", a hard-coded month that started failing in November. It now expects the current month.
