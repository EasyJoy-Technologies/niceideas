# v1.0.98 — 2026-11-23

Posts without text get a name in the admin console, and NiceNote shares that never get content are cleaned up (Xianglin 2026-11-23 15:13 chose option A for the placeholder, 15:21 the 30-day expiry).

## Why
- Staging `/admin/posts` showed an empty, unclickable title for `/p/4zgnbdy4x6xeqe` (@niceideas_e2e_02). It is not an image or audio post: a NiceNote share is created empty (`preparing`) and gets its content with the first push. This one was deleted 1 s after creation, before any push, so it has no title, summary or revision. 17 such posts on staging, all from the e2e account; none on production.
- Images-only or audio-only posts have the same empty title (`cardTitle()` uses only the title and the summary text).

## Changes
- **Admin placeholder (option A):** where a post has no text, the admin pages show a muted "(No content)" (never received any content) or "(No text)" (images / audio only), still linked to the post: posts list, comments list (the post link), report list, report detail (quote and post link), overview top posts. New keys `admin.posts.noContent` / `admin.posts.noText` in all 40 languages. `cardTitle()` and the public pages are unchanged (follow-up suggested separately).
- **Stale shares expire:** the daily maintenance deletes NiceNote shares still `preparing` 30 days after creation, through the usual deletion (page 410, purged after the 30-day retention) and queues `unpublished` for the backend (as for a deletion on the web, so sharing the note again gets a new link). A push that arrives meanwhile wins (the post is re-checked under its lock). Deleted shells keep the normal 30-day retention (unchanged). Report field `preparingExpired`.
- Contract doc `docs/api/nicenote.md` updated (Create; `unpublished` event).

## Database migrations
- `0028_post_preparing_idx`: partial index `post (published_at) WHERE status = 'preparing'` (additive; no row changes).
