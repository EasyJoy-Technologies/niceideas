## Fixed
- F06: media can no longer stay in the public bucket without the database knowing. Every change of which media a live post uses marks them for a check in the same transaction; the check (request right after the commit, worker for anything left) moves them under the media row lock. Publishing still moves media before the commit (no broken images), under a 2-minute lease: a publish that fails or crashes is taken back when the lease ends.
- F12: when a media job settles, the refresh of the shares using it is recorded in the same write; a failed refresh is retried by the worker instead of leaving the post "processing" until the next edit.
- F20: objects written for an upload are recorded before the first write; a failed upload removes them at once, leftovers are removed by the daily maintenance after 24 hours and by the account deletion.
- F15: `media_failed` events are split so each stays ≤ 7000 bytes (the production backend accepts 8 KiB).
- F19: a new profile and its backend registration, and a profile change and its avatar job, are written together.
- F21: audio keeps only title, artist, album, album artist, track, disc, date, genre, composer and comment; cover art, chapters, location, device, encoder and every other tag are dropped. MP3 is now re-wrapped (no re-encoding) instead of stored byte for byte.
- Image renditions: every write finishes before an error is raised (cleanup sees all objects).
