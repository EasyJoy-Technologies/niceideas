# v1.0.18 — 2026-10-20

## Fixes
- The v1.0.17 fix was incomplete: Next compares a proxy rewrite target with the origin it derives from `X-Forwarded-Proto`, so behind nginx (`https`) every rewrite still looked third-party and was proxied to `https://127.0.0.1:3110` (plain HTTP) → profile pages 500, mainland-China site pages served normally instead of 451.
- New mechanism (no absolute URLs anywhere):
  - `src/proxy.ts` only *marks* blocked site requests with an internal header (`x-ni-region-blocked`); an incoming forged marker is always stripped.
  - `next.config.ts` path-only `beforeFiles` rewrites: marked site paths → `/status/region` (451); `/@handle` → `/u/<handle>`.
  - The 451 rewrite only covers the proxy's own paths (shared `SITE_PATH_EXCLUSIONS`, equality tested), so a forged marker can never block `/p/…`, APIs or assets.
- Verified against the built server with nginx headers before deploying.
